# 医疗科普 RAG 系统 — 毕业设计代码审查报告

审查范围：E:\ragsystem 全部后端代码、前端关键文件、脚本与工程配置（只读审查，未改动任何文件）。
审查日期：2026-08-20

## 一、总体评价

**架构是合格的**：FastAPI + LlamaIndex + Chroma + MySQL 分层清晰（api / core / db / crawler / scripts），具备完整 RAG 链路——爬虫采集、TXT 元数据头解析、分块、向量入库、Top-K 检索、阈值拒答、BGE 重排、Prompt 工程、引用来源追加、用户画像记忆。代码注释和文档意识也不错。

**但存在三类问题**：
1. 几个可直接利用的安全漏洞（权限越权、默认口令）——答辩时若被老师或同学试出来，非常难看；
2. 若干功能性 bug，会在演示时翻车（docx 上传乱码、多轮对话历史取错、文档删不掉）；
3. 工程规范缺失（无 README、无测试、无评测数据），这是毕业设计评分的大头扣分项。

## 二、P0 级问题（必须修，含安全漏洞）

### 1. 权限越权漏洞：普通用户可获取管理员权限 ⚠️ 最严重
- 位置：`app/api/auth.py:45-62`（get_current_admin）、`app/api/routes/user.py:22-46`（register）
- 问题：JWT payload 里明明写了 `role` 字段，但 `get_current_admin` **只校验 `sub`（用户名），从不校验 `role`**。而用户注册接口不限制用户名与管理员重名。
- 攻击路径：普通人注册一个和管理员同名的账号（比如默认管理员就叫 `admin`）→ 用该账号登录拿到 token → 直接调用全部 `/api/knowledge/*` 管理员接口（上传、删除、清空知识库）。
- 修法：`get_current_admin` 中校验 `payload.get("role") == "admin"`，`get_current_user` 同理校验 `role == "user"`；注册时禁止与 admins 表已有用户名重复。

### 2. `.docx` 上传后全是乱码
- 位置：`app/api/routes/knowledge.py:84-90`
- 问题：上传分支里只有 `.pdf` 走 `SimpleDirectoryReader`，`.docx` 掉进 else 分支被当成纯文本 `content.decode("utf-8")`——但 docx 是 zip 二进制，解出来是乱码，整篇文档直接废掉却"成功入库"。
- 修法：`.docx` 和 `.html` 也交给 `SimpleDirectoryReader`（LlamaIndex 自带解析器），或 else 分支只保留 `.txt/.md`。

### 3. 爬虫入库的文档删不掉（两条入库链路 metadata 不一致）
- 位置：`scripts/build_index.py:145-179`（enrich_nodes_metadata）vs `app/core/vector_store.py:89-99`（delete_by_doc_id）
- 问题：后台删除文档靠 Chroma metadata 里的 `doc_id` 过滤删除。上传接口链路会注入 `doc_id`，但 **build_index 脚本链路只注入 title/source/url/category，没有 doc_id**。结果是：所有爬虫数据在管理端点"删除"时，MySQL 软删了、Chroma 里的向量一条都删不掉，变成永久幽灵数据。
- 修法：build_index 的 enrich 步骤补注入 `doc_id`（用注册阶段生成的那个），并对存量索引 `--rebuild` 一次。

### 4. 多轮对话历史取的是"最老 20 条"而不是"最近 20 条"
- 位置：`app/api/routes/chat.py:41-47`
- 问题：`.order_by(created_at.asc()).limit(20)`——会话超过 20 条后，取到的永远是最早的 20 条，最近聊的全部丢失，多轮对话直接失忆。
- 修法：先 `desc().limit(20)` 取最近 20 条，再反转为正序。

### 5. 紧急词 / 非医疗词用子串匹配，误拒严重
- 位置：`app/core/prompt.py:25-44`、`207-222`
- 问题：`detect_emergency` 和 `is_non_medical` 是纯中文子串匹配，会误伤正常问题：
  - "**病史**有胃炎要注意什么" → 命中"历史" → 被当非医疗拒答；
  - "食物**中毒**怎么预防" → 命中"中毒" → 直接弹 120 紧急提示；
  - "化**疗**和放疗的区别"不受影响，但"**考试**焦虑导致失眠" → 命中"考试"被拒。
- 修法：至少给非医疗词加"问题整体语境"二次判断（你自己在注释里也写了"命中后只有整体明显非医疗才拒答"，但代码并没有实现这句注释）；或改用关键词 + 否定词表 + LLM 轻量分类兜底。演示前务必自测一批边界 case。

### 6. 上传接口无文件大小限制
- 位置：`app/api/routes/knowledge.py:80`
- 问题：`await file.read()` 一次性读入内存，无任何大小上限。传一个 2GB 文件就能把服务打崩。
- 修法：分块读取并设上限（如 50MB），超限提前 400。

## 三、P1 级问题（重要，建议修）

### 7. 默认口令与 JWT 密钥
- 位置：`app/config.py:53,58-65`；`app/api/routes/admin.py:54-62`
- 问题：MySQL 默认 root/root、管理员默认 admin/admin123，且**每次有人调登录接口都会自动创建这个默认管理员**；JWT_SECRET 硬编码默认值，若 .env 没配就直接用弱密钥上线。
- 修法：启动时校验 JWT_SECRET 不能是默认值（是则拒绝启动或强制随机生成）；默认管理员改为 init 脚本一次性创建并打印强提示。

### 8. 登录无任何防暴力破解措施
- 位置：`app/api/routes/admin.py`、`app/api/routes/user.py` 的 login
- 问题：无失败锁定、无验证码、无限流，可无限撞库。
- 修法：加 slowapi 限流（如每 IP 5 次/分钟）或连续失败临时锁定。

### 9. POST /api/chat 不校验会话归属
- 位置：`app/api/routes/chat.py:27-36`
- 问题：history 接口校验了 session 属于当前用户，但发消息接口不校验——拿到别人的 session_id 就能往别人的会话里写消息。session_id 是 uuid 难以猜中，风险不高但逻辑不自洽。

### 10. 用户画像提取：注释说"异步不阻塞"，实际是同步阻塞
- 位置：`app/api/routes/chat.py:101-109`、`app/core/memory.py`
- 问题：每次回答后**同步**再调一次 LLM 提取画像，用户感知的响应时间直接翻倍；且每次都把最近 20 条全量重新提取，token 浪费。
- 修法：用 `asyncio.create_task` / 后台线程池真正异步化；或改为每 N 轮提取一次、增量提取。

### 11. 参考来源编号与正文角标可能对不上
- 位置：`app/core/engine.py:89-126`（_append_source_list）
- 问题：正文中模型按参考资料原始编号引用 [1][2][3]，但程序追加来源列表时**按 URL 去重后重新从 1 编号**——两条资料同 URL 时，正文的 [3] 在列表里就不存在了。

### 12. rebuild 接口会丢元数据且不同步统计
- 位置：`app/api/routes/knowledge.py:221-232`
- 问题：重建索引用 `build_nodes_from_dir` 直接扫上传目录，上传文件本身没有元数据头，重建后 title/url/category 全丢；也不同步 MySQL 的 chunk_count。
- 修法：rebuild 应以 MySQL documents 表为元数据来源逐文档重建，或直接禁用该接口、统一走 build_index 脚本。

### 13. 分类过滤可能根本没生效
- 位置：`app/core/retriever.py:42-45`
- 问题：`filters={"category": ...}` 以裸 dict 传给 `as_retriever`，新版 LlamaIndex 期望 `MetadataFilters` 对象，行为依赖版本，可能被静默忽略。建议实测：指定分类后是否真的过滤了。

### 14. /uploads 静态目录匿名可访问
- 位置：`app/api/main.py:73-75`
- 问题：上传的知识库原文件挂在公开静态路由下，知道 URL 即可下载。doc_id 随机不易猜，但建议文档类文件至少加 token 校验或移出静态目录，头像单独挂载。

### 15. top_k 无上限
- 位置：`app/api/schemas.py:16`
- 问题：`top_k: int | None` 无上限，传 10 万会拖垮检索。加 `le=50` 即可。

### 16. 头像更新先删旧文件再校验新文件
- 位置：`app/api/routes/admin.py:88-89`、`user.py:78-79`
- 问题：新头像校验失败（400）时旧头像已经被删了。应先校验保存新文件，再删旧的。

## 四、P2 级问题（工程规范，影响评分）

1. **零测试**：全项目没有任何 test 文件。至少补：紧急/非医疗识别的边界用例、分块逻辑、鉴权依赖、上传分支的 pytest 用例 10~20 个。
2. **无 README**：没有项目说明、架构图、启动步骤、环境变量说明。毕业设计没有 README 是明显扣分项。建议提供 `.env.example`。
3. **requirements.txt 有问题**：末尾 `llama-index-core` 重复两行；代码直接 `import torch`（reranker.py）但依赖表没列 torch；版本号全用 `>=` 无锁定，换机器可能装出不兼容版本。建议 `pip freeze` 出一份锁定版。
4. **垃圾/冗余文件**：
   - `web/vite.config.js.timestamp-*.mjs` 两个 vite 临时文件应删除并加入 .gitignore；
   - 根目录 `package.json` + `package-lock.json` 与 `web/` 下的重复，作用不明；
   - `models/bge-reranker-large` 和 `models/models/BAAI--bge-reranker-large/...` 两份重复权重，且同一模型同时保留 `pytorch_model.bin` 和 `model.safetensors`（二选一即可），白白占用数 GB；
   - `logs/install.log`、`.idea/` 建议清理（.gitignore 已覆盖部分）。
5. **死代码 / 未使用引用**：`engine.py` 导入 `SYSTEM_PROMPT_BASE` 未用；`prompt.py` 的 `build_rejected_prompt`、`EMERGENCY_KEYWORDS` 无调用方；`chat.py` 中 `if session_id:` 恒真。
6. **类型标注小错**：`db/models.py` 中 `ChatMessage.sources` 标注 `Mapped[dict]` 但默认值是 list，实际存的也是 list。
7. **前端残留模板痕迹**：`app/api/routes/system.py:56-66` 默认导航是"探索/笔记本/新建笔记"，与医疗场景无关，像未清理的 UI 模板。
8. **管理端无前端页面**：后端 admin/knowledge 接口齐全，但前端 router 只有一个主路由，知识库管理、统计、日志等功能没有对应页面——若答辩要演示管理功能，这是缺口（请确认是否另有安排）。
9. **同步阻塞隐患**：`upload_document` 是 `async def`，但内部 `add_nodes`（含 embedding 计算）是纯同步重活，会阻塞事件循环。建议改回 `def`（FastAPI 自动丢线程池）或用 `run_in_executor`。

## 五、后续改进建议（按性价比排序，面向答辩加分）

### 第一优先：补评测（论文与答辩的核心短板）
目前系统"防幻觉、重排、阈值拒答"全靠自己说好，没有任何量化证据。建议：
1. 手工构造 50~100 条评测问答（覆盖：知识库内问题、知识库外问题、紧急场景、边界词误伤场景）；
2. 指标：检索 Recall@5 / MRR、拒答准确率（该拒不拒、不该拒误拒）、引用来源命中率；
3. 消融对比：有/无 reranker、有/无阈值拒答、不同 chunk_size（300/500/800）。
这套数据能直接写进论文实验章节，是最值钱的改进。

### 第二优先：检索与回答质量
1. 流式输出（SSE）：engine.py 里已留 TODO，前端逐 token 展示，体验提升明显，实现不难；
2. Query 改写：把"那早餐怎么办"这类追问结合历史改写成完整问题再检索，直接解决多轮检索不准；
3. 阈值 0.6 是拍的：用上面评测集扫一遍不同阈值下的拒答准确率曲线，选最优点，论文里就有依据了；
4. 非医疗/紧急判断从关键词升级为"关键词粗筛 + 小模型/规则复核"两级结构。

### 第三优先：安全加固（对应 P0/P1）
role 校验、登录限流、上传大小限制、JWT 密钥强制配置——都是半天内能改完的小改动，但答辩被问到安全时能拿出实际措施。

### 第四优先：工程收尾
README（含架构图、部署步骤、.env.example）+ 10~20 个 pytest 用例 + requirements 锁定 + Docker/docker-compose 一键部署 + alembic 管理表结构变更。
