## 一、严重问题（会导致功能完全不可用）

### 1. `web/package.json` — marked 版本号不存在

**文件**：[package.json:12](file:///e:/ragsystem/web/package.json#L12)

```json
"marked": "^18.0.6"
```

`marked` 最新版本约 14.x/15.x，`^18.0.6` 不是有效版本号，`npm install` 会直接失败，项目无法构建。

**修复建议**：改为 `"marked": "^14.0.0"` 或当前最新稳定版。

---

### 2. `web/src/components/ChatMessage.vue` — XSS 安全漏洞

**文件**：[ChatMessage.vue:10](file:///e:/ragsystem/web/src/components/ChatMessage.vue#L10), [ChatMessage.vue:37](file:///e:/ragsystem/web/src/components/ChatMessage.vue#L37)

```vue
<div v-else class="bubble-content markdown-body" v-html="renderedContent"></div>
```

`marked.parse()` 默认允许原始 HTML 透传。若 AI 返回 `<script>`、`<img onerror=...>` 等恶意标签，会被直接注入 DOM 执行。

**修复建议**：配置 `marked` 禁用原始 HTML，或使用 DOMPurify 对输出进行净化。

---

### 3. `web/src/components/ChatMessage.vue` — Typewriter 链取消失败

**文件**：[ChatMessage.vue:42-61](file:///e:/ragsystem/web/src/components/ChatMessage.vue#L42-L61)

当 `props.message.content` 变化时，旧的 `setTimeout` 链未被 `clearTimeout` 终止，旧闭包继续追加旧内容到 `displayedText`，导致新旧文本混合污染。

**修复建议**：在 watch 回调的起始处调用 `clearTimeout(typewriterTimer)` 终止旧链。

### 4. `crawler/chinacdc.py` — URL 正则错误导致发现不了任何文章

**文件**：[chinacdc.py:50](file:///e:/ragsystem/crawler/chinacdc.py#L50)

```python
ARTICLE_PATTERN = re.compile(r"\./(20\d{4})/t(\d{8})_\d+\.html")
```

`20\d{4}` 匹配的是 **6 位数字**（如 `200000`），正确意图是 `20\d{2}`（4 位年份）。此 bug 导致 `discover_article_links` 几乎永远返回空列表。

### 5. `crawler/chinacdc.py` — 日期从原始 HTML 搜索而非 DOM

**文件**：[chinacdc.py:109](file:///e:/ragsystem/crawler/chinacdc.py#L109)

```python
m = re.search(r"(\d{4})-(\d{2})-(\d{2})", html)  # 在原始HTML中搜索
```

在原始 HTML 字符串中搜索日期，可能匹配到 `<script>` 中的时间戳、其他文章链接中的日期、CSS 注释等，发布日期完全不可靠。

### 6. `crawler/utils.py` — 编码检测启发式完全无效

**文件**：[utils.py:36-44](file:///e:/ragsystem/crawler/utils.py#L36-L44)

```python
html = r.content.decode(enc, errors="ignore")
if "�" not in html and "ä¸" not in html:
    return html
```

`errors="ignore"` 会直接丢弃无法解码的字节，替换字符 `U+FFFD`（`�`）**永远不会出现**，第一条检测永远为 True。`"ä¸"` 只覆盖"UTF-8 被错解为 Latin-1"这一种情形。

### 10. `scripts/build_index.py` — O(N*M) 嵌套循环性能灾难

**文件**：[build_index.py:141-152](file:///e:/ragsystem/scripts/build_index.py#L141-L152)

```python
for node in nodes:                    # N 个 chunk
    for doc_id, doc_path in registered.items():  # M 个文档
        if Path(doc_path).resolve() == fp.resolve():
```

对于 N 个 chunk 和 M 个文档，`Path.resolve()` 每次都做文件系统规范化，时间复杂度 O(N\*M)。当爬取数万篇文章、产生数十万 chunk 时，将严重卡死。

**修复建议**：预先构建 `{resolved_path: doc_id}` 字典，O(1) 查找。
